# 原生语音转写确认

2026-11-08：用户反馈录音说“介绍下创作背景”，讲解却出现“与展品无关”“欢迎来坐坐”。此前未展示原始转写，也未保存当时音频，因此不能由讲解内容认定具体ASR错在哪里。

## 新流程

1. 在Client输入start recording并提交，允许录音。
2. 说完输入stop recording并提交。
3. 模拟器显示识别原文及当前作品，状态为待确认；此时不调用讲解模型。
4. 原文正确，输入confirm并提交，或用Client方向键选择“确认语音”后确认。
5. 不正确，可再次start recording重录；也可直接输入background问当前作品的创作背景、composition问构图、materials问材料。文字修正撤销旧的待确认转写。cancel撤销本次语音。

作品是否正确请看标题。当前不提供摄像头自动识别，选择作品仍由用户完成。

## 验证边界

- 增加近乎静音检测，低信号不发送到ASR；阈值不代表检测到了人声，背景噪声仍可能影响转写。
- 没有修改ASR实际模型，也没有据此声称识别准确率提升。
- 讲解提示增加关注点约束，要求不添加欢迎辞和不以无关概览填补模糊问题；真实生成仍需事实验收。
- 不保存原始录音；识别文字保存在当前应用内存中供核对。
- 本轮原生增加确认步骤，浏览器预览原有转写到文字框后自动发送的流程未改。

## 虚拟机采音环境

本轮检查实际发现：默认音源auto_null.monitor，UTM配置Sound为空。该环境没有配置虚拟声卡，不能据此评价真人ASR准确率。经用户明确同意，正常关闭Ubuntu后备份配置，按UTM官方q35默认硬件配置新增Intel HDA，并重新启动。后续需检查Ubuntu输入源、Mac对UTM的麦克风权限，再真人复测。

官方硬件选择依据：https://raw.githubusercontent.com/utmapp/UTM/main/Configuration/UTMQemuConfigurationSound.swift 。

重启实测：Ubuntu已识别HDA Intel声卡，活动配置为模拟立体声双工；默认输入源为alsa_input.pci-0000_00_03.0.analog-stereo。未自动启动录音，实际Mac麦克风权限、人声采集及ASR准确率仍待用户复测。记录：artifacts/ubuntu-vm/audio-after-reboot.json。
